## 문제 요약

N×N 체스판 위의 K개 말을 번호순으로 이동한다. 이동하는 말과 그 위에 쌓인 말이 함께 이동한다.
흰색 칸에서는 순서를 유지하고, 빨간색 칸에서는 이동하는 말 묶음의 순서만 뒤집는다.
파란색 칸이나 범위 밖이면 해당 말의 방향을 반대로 바꾸고 다시 이동을 시도한다.
반대쪽도 파란색이거나 범위 밖이면 이동하지 않는다.
말이 4개 이상 쌓이는 즉시 게임을 종료하며, 종료 턴을 구한다.

## 입출력

- 입력: 체스판 크기 N, 말 개수 K, N×N 칸 색, K개 말의 행·열·방향. 4 ≤ N ≤ 12, 4 ≤ K ≤ 10.
- 칸 색: 0=흰색, 1=빨간색, 2=파란색.
- 함수: `solution(int n, int k, int[][] board, int[][] pieces)`.
- `board` 배열 인덱스는 0-based다. `pieces[i]`는 i+1번 말이며, 행·열 값은 1-based 원본을 전달한다.
- 방향도 원본 그대로 1=오른쪽, 2=왼쪽, 3=위, 4=아래다. 인덱스 변환은 사용자 풀이 내부에서 수행한다.
- 출력: 종료 턴 번호. 1000턴을 초과하거나 종료되지 않으면 -1.
- 아래는 현재 `input.txt`, `output.txt`의 공식 예제 1이다. 전체 예제는 `examples/baekjoon/17837/`에 보관한다.

## 최종 Solution 코드

```java
import java.util.*;
public class Solution {
    /**
     * @param n 체스판 크기 N (입력값 그대로)
     * @param k 말의 개수 K (입력값 그대로)
     * @param board N×N 칸의 색: 0=흰색, 1=빨간색, 2=파란색.
     *              배열 인덱스는 0-based이며 board[0][0]은 1행 1열.
     * @param pieces K×3 말 정보. pieces[i]는 i+1번 말의 {행, 열, 방향}.
     *               행·열 값은 원본 그대로 1-based.
     *               방향도 원본 그대로 1=오른쪽, 2=왼쪽, 3=위, 4=아래.
     * @return 게임이 종료되는 턴 번호. 1000턴을 초과하거나 종료되지 않으면 -1.
     */
    class Node{
        int x;
        int y;
        int dir;
        Node(int x, int y, int dir){
            this.x =x;
            this.y = y;
            this.dir = dir;
        }
    }
    int[] dxs = {0,0,-1,1};
    int[] dys = {1,-1,0,0};
    Node[] nodes;
    List<Integer>[][] arr;
    public int solution(int n, int k, int[][] board, int[][] pieces) {
        arr = new ArrayList[n][n];
        nodes = new Node[k + 1];
        for(int i = 0; i < n; i++){
            for(int j = 0; j < n; j++){
                arr[i][j] = new ArrayList<>();
            }
        }

        // 초기화
        for(int i = 0; i < k; i++){
            int num = i + 1;
            int x = pieces[i][0] - 1;
            int y = pieces[i][1] - 1;
            int dir = pieces[i][2] - 1;
            arr[x][y].add(num);
            nodes[num] = new Node(x,y,dir);
        }

        int answer = 0;

        while(true){
            if(answer >= 1000) return -1;
            for(int i = 1; i < k + 1; i++) {
                int x = nodes[i].x;
                int y = nodes[i].y;
                int dir = nodes[i].dir;

                int nx = x + dxs[dir];
                int ny = y + dys[dir];
                if (!inRange(nx, ny, n) || board[nx][ny] == 2) {
                    dir = (5 - dir) % 4;
                    nodes[i].dir = dir;
                    nx = x + dxs[dir];
                    ny = y + dys[dir];
                    if (!inRange(nx, ny, n) || board[nx][ny] == 2) continue;
                    if (board[nx][ny] == 0) {
                        doWhite(i, x, y, nx, ny);
                        if(arr[nx][ny].size() >= 4){
                            return answer + 1;
                        }
                    } else {
                        doRed(i, x, y, nx, ny);
                        if(arr[nx][ny].size() >= 4){
                            return answer + 1;
                        }
                    }
                } else if (board[nx][ny] == 0) {
                    doWhite(i, x, y, nx, ny);
                    if(arr[nx][ny].size() >= 4){
                        return answer + 1;
                    }
                } else {
                    doRed(i, x, y, nx, ny);
                    if(arr[nx][ny].size() >= 4){
                        return answer + 1;
                    }
                }
            }
            answer += 1;
        }
    }

    private void doWhite(int num, int x, int y, int nx, int ny){
        int size = arr[x][y].size();
        int index = arr[x][y].indexOf(num);
        for(int i = index; i < size; i++){
            int number = arr[x][y].get(index);
            arr[nx][ny].add(number);
            arr[x][y].remove(index);
            nodes[number].x = nx;
            nodes[number].y = ny;
        }
    }

    private void doRed(int num, int x, int y, int nx, int ny){
        int size = arr[x][y].size();
        int index = arr[x][y].indexOf(num);
        for(int i = size - 1; i >= index; i--){
            int number = arr[x][y].get(i);
            arr[nx][ny].add(number);
            arr[x][y].remove(i);
            nodes[number].x = nx;
            nodes[number].y = ny;
        }
    }

    private boolean inRange(int nx, int ny, int n){
        return nx >= 0 && nx < n && ny >= 0 && ny < n;
    }
}
```

## 처음 접근

약 3시간 동안 `Node`의 `parent`, `child`로 위아래 말을 연결하는 시뮬레이션을 구현했다.
각 칸에는 맨 아래 말 번호만 저장하고, 연결을 따라 위쪽 말의 이동·뒤집기·높이 계산을 처리하려 했다.
사용자는 위아래 노드 연결에 결함이 있는 것으로 의심했고, 미완성 상태에서 1차 시도를 보관하도록 요청했다.

- [1차 시도 전체 원본](../../../attempts/baekjoon/17837/attempt-01/Solution.java)
- [당시 메모](../../../attempts/baekjoon/17837/attempt-01/notes.txt)

## 처음 틀렸던 점

- 사용자 진단: 말의 위아래 연결 관계에 결함이 있는 것으로 추정.
- 온라인 오답 제출 여부 및 재현 입력·출력: 기록되지 않음. 1차 시도를 보관할 때는 채점하거나 수정하지 않았다.
- 기록 시점 코드에서 확인되는 문제: 출발 칸의 연결 해제, 도착 칸의 연결 설정, 칸의 맨 아래 말 갱신이 색별 분기에서 일관되지 않았다. 특히 아래 빨간색 분기는 기존 부모 연결을 해제한 직후 `parent == 0`을 검사하므로, 아래에 남은 말이 있어도 출발 칸을 0으로 덮어쓸 수 있다.

당시 실제 코드의 핵심 부분:

```java
// 움직일때 만약 아래에 말이 있다면
if(parent != 0){
    nodes[parent].child = 0;
    nodes[num].parent = 0;
}
// 부모가 없으면 해당 칸은 0으로 갱신
if(nodes[num].parent == 0){
    arr[x][y] = 0;
}
```

또한 기존 빨간색 분기의 `reverse(next)`는 도착 칸의 기존 말까지 뒤집는 구조였고,
파란색 이후 재시도에는 도착 칸의 빨간색 처리가 구분되어 있지 않았다.
종료 조건도 턴 전체 이동 후 `depth != 4`로 확인했으므로, 매 이동 직후 4개 이상인지 확인하는 조건과 달랐다.
이 내용은 보관 코드의 정적 검토이며, 특정 실패 테스트로 확인한 결과는 아니다.

## 수정 과정

1. 1차 시도 원본과 당시 접근·사용자 진단을 별도로 보관했다.
2. 사용자의 요청으로 `Solution.java`를 빈 템플릿으로 초기화했다.
3. 사용자가 각 칸의 쌓인 말 번호를 `List<Integer>`로 관리하는 방식으로 다시 작성했다. `Node`에는 위치와 방향만 남겼다.
4. 흰색은 이동 시작 인덱스부터 같은 인덱스의 원소를 반복해서 꺼내고, 빨간색은 끝에서부터 꺼내 도착 칸에 추가했다.
5. 방향 반전 뒤에도 실제 도착 칸의 색에 맞는 함수를 호출하고, 매 이동 직후 말이 4개 이상이면 즉시 종료하도록 했다.
6. 제출 파일의 공식 예제 5개 통과 후 사용자가 온라인 정답을 확인했다.
7. 기록 시점에는 사용하지 않는 `checkDepth()`가 제거된 최종 코드가 확인되어 이를 원형 그대로 기록하고 제출 파일에도 반영했다.

외부 정답 코드의 실제 참조 여부나 출처는 기록되지 않음.

## 핵심 아이디어

- `arr[x][y]`는 아래에서 위 순서의 말 번호 목록이다. 각 말의 위치·방향은 `nodes`에 저장한다.
- 현재 말의 인덱스를 찾고, 그 인덱스부터 끝까지의 말만 이동한다.
- 흰색은 순서를 유지하고 빨간색은 이동 묶음만 뒤집으며, 기존 도착 칸의 말 순서는 유지한다.
- 함께 이동한 모든 말의 좌표를 갱신한다. 방향 반전은 이동 차례인 말에만 적용한다.
- 매 이동 직후 종료 조건을 검사하며, 1000번째 턴까지는 정상적으로 수행한다.

## 복잡도

T는 실제 수행 턴 수이며 T ≤ 1000이다.

- 시간 복잡도: O(N² + T×K). 게임이 계속되는 동안 한 칸에는 최대 3개의 말만 있으므로, 각 이동의 리스트 검색·삭제·추가는 상수 범위다. 4개 이상이 되는 이동 직후 즉시 종료한다.
- 공간 복잡도: O(N² + K). 칸별 리스트, 보드, 말 정보와 전체 K개의 말 번호를 저장한다.

## 반례와 경계 조건

- 최소 입력: N=4, K=4. 한 번의 이동으로 4개가 쌓이면 해당 턴에 바로 종료한다.
- 최대 입력: N=12, K=10. 1000번째 턴에서 종료하면 1000을 반환하고, 그 턴까지 종료되지 않으면 -1을 반환한다.
- 중간에 있는 말이 이동하면 아래쪽 말은 원래 칸에 남는다.
- 빨간색 칸의 기존 말은 뒤집지 않고 새로 이동한 묶음만 뒤집는다.
- 파란색/경계에서 반전 후 다시 막혀도 바뀐 방향은 유지한다.
- 반전 후 빨간색 칸으로 이동하면 빨간색 규칙을 적용한다.
- 함께 이동한 말도 이후 자기 번호 차례가 오면 현재 위치에서 다시 이동한다.
- 쌓인 수가 정확히 4인 경우뿐 아니라 4를 초과하는 경우도 즉시 종료한다.
