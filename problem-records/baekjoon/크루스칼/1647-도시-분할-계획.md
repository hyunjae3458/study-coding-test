# 백준 1647 - 도시 분할 계획

## 문제 정보

- 플랫폼: 백준 온라인 저지
- 문제 번호: 1647
- 난이도: 골드 IV (solved.ac, 2026-08-04 확인)
- 문제 링크: https://www.acmicpc.net/problem/1647
- 풀이 날짜: 2026-08-04
- 결과: 정답
- 검증: 로컬 확장 채점 전체 통과 및 백준 반례 찾기 사이트에서 반례 미발견

## 문제 요약

연결된 마을의 집들을 두 개의 분리된 마을로 나누고, 각 마을 안의 집들은 서로
이동할 수 있게 유지한다. 두 마을 사이의 길은 필요하지 않을 때 전체 길 유지비의
최솟값을 구한다.

## 입출력

- 입력: 집의 수 `N`, 길의 수 `M`, 그리고 `M`개의 길 `A B C`
- 출력: 두 마을에서 유지할 길의 비용 합의 최솟값

## 최종 코드

```java
import java.util.*;

public class Solution {
    int[] parents;
    int[] size;

    public long solution(int houseCount, int[][] roads) {
        parents = new int[houseCount + 1];
        size = new int[houseCount + 1];

        for (int i = 1; i < houseCount + 1; i++) {
            parents[i] = i;
            size[i] = 1;
        }

        Arrays.sort(roads, (a, b) -> Integer.compare(a[2], b[2]));

        long answer = 0L;
        int max = Integer.MIN_VALUE;
        for (int[] road : roads) {
            int start = road[0];
            int end = road[1];
            int cost = road[2];

            if (find(start) != find(end)) {
                union(start, end);
                answer += cost;
                max = Math.max(max, cost);
            }
        }
        return answer - max;
    }

    private int find(int curr) {
        if (parents[curr] == curr) return curr;
        return parents[curr] = find(parents[curr]);
    }

    private void union(int a, int b) {
        int rootA = find(a);
        int rootB = find(b);

        if (rootA == rootB) return;

        if (size[rootA] < size[rootB]) {
            int temp = rootA;
            rootA = rootB;
            rootB = temp;
        }

        parents[rootB] = rootA;
        size[rootA] += size[rootB];
    }
}
```

## 처음 접근

비용이 작은 길부터 선택해 모든 집을 연결한 뒤, 선택된 길 중 가장 유지비가 큰 길을
제외해 두 마을로 나누었다. 집합 연결 여부는 경로 압축을 적용한 서로소 집합으로
관리했다.

## 처음 틀렸던 점

- 공식 예제와 무작위 테스트는 통과했지만, 최대 깊이 테스트에서
  `StackOverflowError`가 발생했다.
- 첫 `union`은 집합 크기를 고려하지 않고 항상 한쪽 루트를 다른 쪽에 연결했다.
- 입력 순서에 따라 부모 관계가 최대 100,000단계까지 한쪽으로 길어질 수 있었다.
- 경로 압축을 사용해도 그 긴 경로를 처음 탐색하는 재귀 호출에서 스택이 넘칠 수 있었다.

실패 입력의 구성은 다음과 같았다.

```text
N = 100000, M = 100000
(2, 1, 1), (3, 2, 1), ..., (100000, 99999, 1), (1, 100000, 1)
```

- 기댓값: `99,998`
- 실제 결과: `StackOverflowError`

## 수정 과정

각 루트가 가진 집합 크기를 `size` 배열에 저장했다. 두 집합을 합칠 때 크기가 작은
집합의 루트를 큰 집합의 루트 아래에 연결하도록 Union by size를 적용했다. 수정 후
이전에 실패한 100,000단계 구성에서도 `99,998`을 정상 반환했다.

## 핵심 아이디어

- 길을 유지비 오름차순으로 정렬한다.
- 서로 다른 집합을 잇는 길만 선택한다.
- 모든 집을 연결할 때 선택한 길 중 유지비가 가장 큰 길 하나를 제외한다.
- 경로 압축과 Union by size를 함께 사용해 부모 트리의 깊이를 제한한다.
- 유지비 합은 `long`으로 누적한다.

## 복잡도

- 시간 복잡도: `O(M log M)`
- 공간 복잡도: `O(N)` (입력 길 배열 제외)

## 반례와 경계 조건

- 집이 두 개뿐인 경우
- 같은 두 집 사이에 여러 길이 있는 경우
- 모든 길의 유지비가 같은 경우
- 두 지역을 잇는 길의 비용이 매우 큰 경우
- 부모 트리가 한쪽으로 깊어질 수 있는 입력 순서
- 집 100,000개와 길 1,000,000개의 최대 규모 입력

## 검증 결과

- 공식 및 고정 테스트 6개: 전부 통과
- 무작위 교차검증 500개: 전부 통과
- 이전 스택 오버플로우 테스트: 통과
- 최대 규모 테스트: 통과
- 최대 규모: 집 100,000개, 길 1,000,000개
- 최대 규모 기댓값/실제값: `99,998` / `99,998`
- 백준 반례 찾기 사이트: 반례 미발견
